## 一、30 秒速查

| 我想… | 怎么做 |
|---|---|
| 写一篇新文章 | 在 `src/content/posts/` 下新建 `xxx.md`（或用 `pnpm new-post -- xxx`） |
| 放文章里的图片 | 放在文章同目录或 `src/content/posts/images/`，正文写 `![说明](./images/a.png)` |
| 让别人下载 zip/pdf | 文件放 `public/files/...`，frontmatter 加 `attachments:`（见 [第五章](#五分享文件附件下载)） |
| 给文章加密码 | frontmatter 加 `password: 你的密码`（见 [第六章](#六给文章上锁密码访问)） |
| 先不发布 | `draft: true`（本地能看，正式构建自动剔除） |
| 置顶 | `pinned: true` |
| 本地预览 | `pnpm dev` → http://localhost:4321 |
| 正式构建 | `pnpm build`（含搜索索引）；只想验证用 `pnpm build:fast` |

## 二、文章写在哪里

### 2.1 目录与 URL 的对应关系

**所有文章都放在 `src/content/posts/` 下**，支持 `.md` 和 `.mdx`，支持子目录。

| 文件路径 | 访问 URL |
|---|---|
| `src/content/posts/hello.md` | `/posts/hello/` |
| `src/content/posts/guide/index.md` | `/posts/guide/` |
| `src/content/posts/tech/astro.md` | `/posts/tech/astro/` |
| `src/content/posts/code-examples.mdx` | `/posts/code-examples/` |

规则：

- **文件名（含子目录、去掉扩展名）就是 URL**，改文件名 = 改链接，旧链接会 404；
- 目录里的 `index.md` 会变成目录本身的页面；
- 站点强制尾部斜杠（`trailingSlash: "always"`），链接一律以 `/` 结尾；
- **建议文件名用小写英文 + 连字符**（`my-first-post.md`）。中文名能用，但 URL 会被百分号编码，分享出去又长又丑。

### 2.2 新建文章

方式 A —— 用脚本（自动生成带日期的 frontmatter 骨架）：

```bash
pnpm new-post -- my-first-post
# 生成 src/content/posts/my-first-post.md
# 已存在同名文件会报错退出，不会覆盖
```

脚本生成的骨架只有 7 个字段，够用；需要 **附件 / 密码 / 置顶** 等要自己往下加（见第三、五、六章）。

方式 B —— 手动新建：复制下面这份「全字段模板」，用不到的整行删掉即可（所有可选字段都有默认值，不写不会报错）。

```markdown
---
title: 文章标题
published: 2026-09-25
updated: 2026-09-25
description: 一句话摘要，显示在列表卡片和搜索结果里
image: ./images/cover.avif
tags: [Astro, 教程]
category: 技术笔记
pinned: false
draft: false
comment: true
author: 你的名字
sourceLink: https://example.com/original
lang: zh_CN

# 附件下载（见第五章）
attachments:
  - path: files/my-first-post/demo.zip
    name: 演示压缩包
  - path: files/my-first-post/report.pdf

# 密码保护（见第六章，不要和密码文章同时用错）
# password: "123456"
# passwordHint: 提示：我的生日
---

正文从这一行开始写。
```

### 2.3 图片放哪里

两种方式，别混用：

| 放法 | 写法 | 是否被优化 | 适用场景 |
|---|---|---|---|
| **放在 `src/` 下（推荐）** | `![图注](./images/a.png)` 或 `![图注](../images/a.png)` | ✅ 自动压缩转 WebP（质量 85） | 文章配图、封面 |
| 放在 `public/` 下 | `![图注](/assets/images/a.png)` | ❌ 原样拷贝 | 二维码、需要保持原图的资源 |

注意：

- `./` 这种**相对路径只对 `src/` 下的图片生效**；`public/` 下的文件必须用 `/` 开头的绝对路径；
- **写了 alt 文字就会自动变成图注**（渲染成 `<figure><figcaption>`）。不想显示图注就别写 alt：`![](./a.png)`；
- 站点只优化 `src/` 目录里的图片，`src/` 里图越多构建越慢。

## 三、frontmatter 全部字段

来源：`src/content.config.ts`。**只有 `title` 和 `published` 是必填**，其余都有默认值，不写就是默认值。

| 字段 | 类型 | 默认 | 作用 |
|---|---|---|---|
| `title` | 字符串 | **必填** | 文章标题 |
| `published` | 日期 | **必填** | 发布日期，必须写成 `2026-09-25`（**不要加引号**） |
| `updated` | 日期 | 空 | 更新日期。距今天数超过 `siteConfig.outdatedThreshold`（默认 30 天）时，文章底部显示「上次编辑」卡片 |
| `description` | 字符串 | 空 | 摘要。**留空则自动取正文第一段** |
| `image` | 字符串 | 空 | 封面图。支持 `./images/x.avif`（src，优化）、`/files/x.png`（public）、`https://...` |
| `tags` | 数组 | `[]` | 标签，可多个 |
| `category` | 字符串 | 空 | 分类，**只能一个** |
| `pinned` | 布尔 | `false` | 是否置顶 |
| `draft` | 布尔 | `false` | 草稿。`true` 时**本地 dev 仍可见，正式构建会被剔除** |
| `comment` | 布尔 | `true` | 单篇文章是否显示评论区（还要先启用评论系统） |
| `author` | 字符串 | 空 | 作者，用于底部版权卡 |
| `sourceLink` | 字符串 | 空 | 原文链接（转载时用） |
| `licenseName` / `licenseUrl` | 字符串 | 空 | 覆盖站点默认的版权协议（默认在 `src/config/licenseConfig.ts`） |
| `lang` | 字符串 | 空 | 文章语言，留空跟随站点 |
| `password` | 字符串 | 空 | 文章密码，**填了就上锁**（见第六章） |
| `passwordHint` | 字符串 | 空 | 密码提示，显示在锁屏界面上 |
| `attachments` | 数组 | `[]` | 附件下载列表（见第五章） |
| `attachmentsProtected` | 布尔 | `false` | `true` 时不渲染下载区块（**文件仍可被直链下载**，不能当权限用） |

> 写错字段名不会报错，只会**静默失效**（例如把 `pinned` 拼成 `pin` 就永远不置顶）。拿不准就照上表复制。

## 四、Markdown 语法支持矩阵

### 4.1 一句话结论

**标准 Markdown + GFM（GitHub 风格）全部可用**，此外还额外支持：代码增强、数学公式、流程图、提醒框、GitHub 卡片、图片网格。不支持的只有少数冷门扩展（见 4.9）。

### 4.2 基础语法

| 语法 | 支持 | 备注 |
|---|---|---|
| 标题 `#` ~ `######` | ✅ | 自动生成 id，右侧浮动目录自动收录 |
| 粗体 / 斜体 / 删除线 `~~x~~` | ✅ | |
| 有序 / 无序 / 嵌套列表 | ✅ | |
| 链接、图片、引用 `>` | ✅ | |
| 行内代码、围栏代码块 | ✅ | 由 Expressive Code 渲染 |
| 表格（GFM） | ✅ | |
| 任务列表 `- [x]`（GFM） | ✅ | |
| 分隔线 `---` | ✅ | |
| 原生 HTML | ✅ | 可直接写 `<div>`、`<kbd>` 等 |
| 自动链接（GFM） | ✅ | |

### 4.3 代码块（Expressive Code）

````markdown
```js title="src/main.js" {2-3} ins={4} del={5}
function hello() {
  const a = 1;   // 这两行被高亮
  return a;
  // 新增行
  // 删除行
}
```
````

- 语法高亮、行号、右上角复制按钮默认开启；
- `title="..."` 显示文件名标题栏；`{2-3}` 高亮行；`ins={} / del={}` 增删标记；
- 长代码块是否默认折叠、是否显示语言徽标，由 `src/config/expressiveCodeConfig.ts` 控制；
- 用 `ansi` 语言可渲染 ANSI 彩色输出。

### 4.4 数学公式（KaTeX）

```markdown
行内：$E = mc^2$

块级：
$$
\int_0^1 x^2 \, dx = \frac{1}{3}
$$
```

已加载 mhchem 扩展，化学方程式可用 `\ce{H2O}`。

### 4.5 图表

````markdown
```mermaid
graph LR
  A[开始] --> B{判断}
  B -->|是| C[结束]
```
````

PlantUML 同理，语言标识写 `plantuml`（配置在 `src/config/plantumlConfig.ts`）。

### 4.6 提醒框（Admonition）

当前主题是 `github`（在 `siteConfig.rehypeCallouts.theme` 切换），两种写法等价：

```markdown
> [!NOTE]
> 这是提示内容

> [!WARNING] 自定义标题
> 警告内容
```

或用 directive 写法（可带标题）：

```markdown
:::note
提示内容
:::

:::warning[自定义标题]
警告内容
:::
```

可用类型：`note` `tip` `important` `warning` `caution` `info` `success` `question` `danger` `error` `bug` `example` `quote` 等（完整清单见 `src/plugins/remark-directive-rehype.js`）。

### 4.7 GitHub 仓库卡片

```markdown
::github{repo="CuteLeaf/Firefly"}
```

### 4.8 图片网格

```markdown
[grid]
![图一](./images/a.png)
![图二](./images/b.png)
![图三](./images/c.png)
[/grid]
```

按图片数量自动 1~4 列，移动端单列。

### 4.9 不支持 / 需要注意

| 语法 | 情况 |
|---|---|
| 脚注 `[^1]` | ❌ 未启用插件，会原样显示 |
| `==高亮==` | ❌ 未启用插件，不会渲染成高亮 |
| 表情简写 `:smile:` | ❌ 未启用 |
| `.mdx` 里的 JSX | ✅ 支持，但 `.md` 里写 JSX 无效 |
| 表格里写复杂 HTML | 谨慎，容易渲染错乱 |

另外两个自动行为，不用自己写：

- **外链**：正文里指向站外的 `http(s)://` 链接会自动加 `target="_blank" rel="noopener noreferrer"`（本站域名除外，域名取 `siteConfig.site_url`）；
- **邮箱**：正文里的邮箱地址会被自动保护（base64），防爬虫。

## 五、分享文件（附件下载）

### 5.1 一句话流程

**文件放 `public/` 下 → frontmatter 里声明路径 → 构建时自动算大小 → 文章底部出现下载卡片。**

### 5.2 文件放在哪

放在 **`public/files/`** 下（推荐按文章建子目录，便于管理）：

```
public/
└── files/
    └── my-first-post/
        ├── demo.zip
        ├── report.pdf
        └── page.html
```

`public/` 里的文件会**原样**拷进构建产物，路径即 URL：`public/files/my-first-post/demo.zip` → `https://你的域名/files/my-first-post/demo.zip`。

### 5.3 frontmatter 写法

```yaml
attachments:
  - path: files/my-first-post/demo.zip
    name: 演示压缩包
  - path: files/my-first-post/report.pdf
  - path: /files/my-first-post/page.html
    name: 单页 HTML
  - path: https://example.com/share/big-file.zip
    name: 外链资源（体积未知）
```

要点：

| 项 | 说明 |
|---|---|
| `path` | **站点根相对路径**（即 `public/` 内部的路径）。带不带开头的 `/` 都可以，程序会自动去掉 |
| `name` | 显示名，**可省略**，省略时用文件名（去掉扩展名） |
| 外链 | 以 `http://` 或 `https://` 开头 → 当作外链，体积显示 `—` 并标注「外链」 |
| 体积 | **构建期自动读取磁盘大小**，不要手写，也不会过期 |
| 徽标 | 按扩展名自动显示 `ZIP` `PDF` `HTML` `DOC` `IMG` `VIDEO` 等 |
| 下载行为 | 链接带 `download` 属性并在新标签打开 |

### 5.4 两条硬规则

1. **本地文件找不到 → 构建直接失败**，并打印期望的完整路径。这是故意设计的：坏下载链接是真实缺陷，宁可构建时拦下，也不要上线一个点了 404 的按钮。
   ```
   [attachments] 文章 "my-first-post" 声明的附件在磁盘上找不到：files/my-first-post/demo.zip
     期望位置：D:\blog\starseeker\public\files\my-first-post\demo.zip
   ```
   处理：把文件放到对应位置，或改用 `https://` 外链，或删掉这一条。

2. **`attachmentsProtected: true` 只是「不显示区块」，不是访问控制。** 文件仍躺在 `public/` 里，知道 URL 就能下。真正私密的东西不要放 `public/`。

### 5.5 加密文章里的附件

附件区块在加密容器内部 → **必须输入正确密码才会显示**。但同 5.4 第 2 条：文件本身只要 URL 暴露就能下载。要保密就别放 `public/`，改用需要鉴权的网盘外链。

### 5.6 演示文件（可以删）

仓库里带了一份演示，验证完可以整体删掉：

- `public/files/code-examples/demo-attachment.zip`
- `public/files/code-examples/demo-attachment.pdf`
- `src/content/posts/code-examples.md` frontmatter 里的 `attachments:` 整段（含上面那行注释）

删之前可以先跑 `pnpm dev` 打开 `/posts/code-examples/`，文章底部就是附件区块的实际样子（卡片 + 类型徽标 + 体积 + 下载图标）。

## 六、给文章上锁（密码访问）

### 6.1 写法

```yaml
---
title: 私密文章
published: 2026-09-25
password: "123456"
passwordHint: 提示：我的生日
---
```

只要 `password` 非空，文章正文就会被锁住，访客看到的是密码输入框；输入正确后正文就地解密显示，**同一标签页内刷新不用重输**（密码缓存在 `sessionStorage`，关掉标签页即失效）。

### 6.2 它是怎么工作的

1. 构建时：PBKDF2（10 万次迭代，SHA-256）从密码派生密钥 → AES-256-GCM 加密正文 HTML；
2. 页面里只有密文，没有明文；
3. 浏览器端输入密码 → 解密 → 注入页面；密码错误给出错误提示。

> 实现细节（不用改，仅供理解）：盐和 IV 由「密码 + 文章 slug」确定性派生，不是随机数 ——
> 这样**相同输入永远得到相同密文**，密码缓存才能在刷新后继续用。
> 副作用是：改了密码后，浏览器里缓存的旧密码会解密失败并自动清除，访客需要重新输入。

### 6.3 ⚠️ 安全边界（务必看）

| 项 | 是否受保护 |
|---|---|
| 正文内容 | ✅ 受保护（HTML 里只有密文） |
| 标题、摘要、标签、分类、封面图 | ❌ **明文**，列表页和搜索结果里都能看到 |
| 仓库里的 `.md` 源文件 | ❌ **明文**（如果仓库公开，等于没锁） |
| 附件文件（`public/`） | ❌ 不在加密范围内 |

所以它是**防君子不防小人**的轻量保护：适合「先藏着、别让随手点进来的人看到」，不适合放真正的机密。真要保密：正文别写进仓库、附件别放 `public/`、摘要里别剧透。

### 6.4 其它注意

- 改密码后**必须重新构建**才生效（加密发生在构建期）；
- 加密文章里的图表（Mermaid 等）在解密后会重新初始化，正常显示；
- 密码不要用 YAML 特殊字符开头（`#`、`@`、`*` 等），用引号包起来最保险（如上例）。

## 七、其它常用操作

### 7.1 草稿 / 置顶 / 评论

```yaml
draft: true      # 本地 dev 能看到，正式构建自动剔除（用于写到一半）
pinned: true     # 置顶
comment: false   # 这篇不显示评论区
```

### 7.2 独立页面（关于我 / 留言板）

内容在 **`src/content/spec/`** 下的 Markdown，直接改文件即可，**不要去改 `.astro` 页面**：

| 页面 | 内容文件 |
|---|---|
| 关于我 | `src/content/spec/about.md` |
| 留言板 | `src/content/spec/guestbook.md` |

页面是否启用在 `src/config/siteConfig.ts` 的 `pages`（`friends` / `sponsor` / `guestbook` / `bangumi` / `gallery`，`false` 会返回 404）。

### 7.3 站点配置在哪改

全部在 `src/config/` 下，改完**重启 `pnpm dev`**：

| 想改什么 | 改哪个文件 |
|---|---|
| 站点标题、描述、主题色、页面开关、分页、统计 | `siteConfig.ts` |
| 头像、昵称、签名、社交链接 | `profileConfig.ts` |
| 导航菜单 | `navBarConfig.ts` |
| 侧边栏组件 | `sidebarConfig.ts` |
| 评论系统 | `commentConfig.ts` |
| 公告、页脚、友链、相册、赞助 | `announcementConfig.ts` / `footerConfig.ts` / `friendsConfig.ts` / `galleryConfig.ts` / `sponsorConfig.ts` |
| 代码高亮主题、字体、特效（樱花等）、背景壁纸、音乐播放器 | `expressiveCodeConfig.ts` / `fontConfig.ts` / `effectsConfig.ts` / `backgroundWallpaper.ts` / `musicConfig.ts` |

### 7.4 字号调节（读者侧）

读者可以在显示设置面板里调正文大小（小 / 标准 / 大 / 特大），偏好存本地，不影响你的写作。

## 八、构建与发布

```bash
pnpm dev          # 本地预览 http://localhost:4321（草稿也可见）
pnpm build        # 正式构建：图标生成 → 图片占位图 → astro build → 看板娘资源 → pagefind 搜索索引
pnpm build:fast   # 同上但跳过搜索索引（本地快速验证用，不要拿去部署）
pnpm preview      # 预览构建产物
pnpm check        # 类型检查（项目有 35 个历史基线错误，对比数量即可）
pnpm lint         # 代码格式化 + 检查（改源码时用）
```

发布要点：

- **搜索只在 `pnpm build` 后才有索引**；用 `build:fast` 部署会导致站内搜索搜不到东西；
- 产物在 `dist/`，可直接托管（Vercel / Cloudflare Pages / 任意静态服务器）；
- Cloudflare 走 `wrangler.jsonc`（`assets.directory: ./dist`），需 SSR 时设环境变量 `CF_WORKERS=1`；
- 每次改文章都要重新构建才会上线。

## 九、常见坑与排查

| 现象 | 原因 / 处理 |
|---|---|
| 构建报 `published` 相关错误 | 日期必须是 `2026-09-25` 这种格式，**且不能加引号** |
| 附件区块没出现 | ① 区块只在该文章声明了 `attachments` 时显示；② `attachmentsProtected: true` 会隐藏；③ 本地文件必须先放进 `public/` |
| 构建报「附件在磁盘上找不到」 | 见 [5.4](#54-两条硬规则)：路径写错或文件没放，按报错里的期望路径放好 |
| 草稿本地能看到、上线后没有 | 正常行为，`draft: true` 在生产构建中被过滤 |
| 站内搜不到刚发的文章 | 用了 `build:fast`（没有搜索索引），改用 `pnpm build` |
| 改了 `src/config/*.ts` 没生效 | 配置文件改动需重启 `pnpm dev` |
| 图片不显示 | 相对路径 `./` 只对 `src/` 下图片有效；`public/` 下的必须以 `/` 开头 |
| 图片被压缩糊了 | `src/` 下的图会被优化；要原样输出就放 `public/` 并用 `/` 路径 |
| 提醒框没生效 | 当前是 github 主题，语法必须是 `> [!NOTE]` 或 `:::note`，写错类型名会原样输出 |
| 改了文件名后旧链接 404 | 文件名即 URL，改名等于换地址，需要保留旧链接就留一份同名文件做跳转说明 |
| 加密文章标题/摘要还是能看到 | 设计如此，见 [6.3](#63-️-安全边界务必看) |
| 新加的图标不显示 | `src/constants/icons.ts` 是白名单，改完要跑 `pnpm icons` 重新生成 |
