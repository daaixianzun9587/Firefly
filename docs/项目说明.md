# Firefly 项目说明（新人上手）

> 面向**刚接手本项目**的开发人员。目标：读完能理解项目是什么、代码在哪、数据怎么流、怎么跑起来、改哪些地方会出事。
> 术语与命名**与代码保持一致**（配置对象名、函数名、文件路径均可直接对照检索）。
> 本文档不含任务排期与待办内容。

## 1. 项目定位与核心功能

**Firefly** 是一个基于 **Astro 6** 的**静态博客主题/站点**（`package.json`：`name: "firefly"`，`version: 6.10.9`）。输出**纯静态站点**（`output: "static"`），部署到 Cloudflare Pages/Workers 或 Vercel。

核心能力：

| 能力 | 说明 | 主要实现位置 |
|---|---|---|
| 文章与独立页面 | Markdown / MDX，内容集合 `posts` / `spec` | `src/content.config.ts`、`src/pages/posts/[...slug].astro` |
| 主题与配色 | 浅/深/跟随系统，色相 `--hue` 可调，首屏无闪 | `src/utils/setting-utils.ts`、`src/layouts/Layout.astro` |
| 显示设置面板 | 壁纸模式、色相、布局、樱花、水波、正文字号等 | `src/components/controls/DisplaySettingsIntegrated.svelte` |
| 侧栏小部件系统 | 组件顺序/位置/响应式由配置驱动 | `src/config/sidebarConfig.ts`、`src/components/widget/*` |
| 站内导航（SPA 化） | swup 接管跳转，局部替换容器 | `astro.config.mjs` 的 `swup()`、`src/utils/navigation-utils.ts` |
| 搜索 | 构建期生成索引（pagefind），运行期检索 | `pnpm build` 末步、`src/components/controls/Search.svelte` |
| 音乐播放器 | Meting API 或本地列表，全局单例管理器 | `src/components/features/MusicManager.astro`、`MusicPlayer.astro` |
| 看板娘 | Spine 模型 / Live2D 看板娘（**默认关闭**） | `src/components/features/SpineModel.astro`、`Live2DWidget.astro` |
| 图片与 LQIP | AVIF 优化 + 占位渐变 | `scripts/generate-lqips.ts`、`src/utils/lqip-utils.ts` |
| 多语言界面 | 5 种界面语言，非 i18n 路由 | `src/i18n/` |
| 加密文章、KaTeX、Mermaid、PlantUML、图库、番剧页、RSS、OG 图 | 见 §4 插件部分 | `src/plugins/`、`src/pages/` |

## 5. 核心业务流程与数据流转

### 5.1 内容：Markdown → 页面

```
src/content/posts/**/*.{md,mdx}
  └─ content.config.ts（glob loader + zod schema）→ 集合 posts
      └─ content-utils.getSortedPosts()（置顶优先、草稿在 PROD 过滤）
          ├─ 首页分页   pages/[...page].astro
          ├─ 归档/标签/分类  pages/archive|tags|categories
          ├─ 文章页     pages/posts/[...slug].astro
          │    ├─ getRelatedPosts(entry, 5) → RecommendedPost 左栏（构建期直出）
          │    └─ Markdown.astro → .custom-md
          └─ api/allPostMeta.json.ts → 运行期给「随机文章」和「日历」用
```

**文章 frontmatter 字段**（`content.config.ts` 的 zod schema）：
`title`、`published`、`updated?`、`draft?`、`description?`、`image?`、`tags?`、`category?`、`lang?`、`pinned?`、`author?`、`sourceLink?`、`licenseName?`、`licenseUrl?`、`comment?`、`password?`、`passwordHint?`，以及内部使用的 `prevTitle/prevSlug/nextTitle/nextSlug`。

### 5.2 构建流程（`pnpm build`）

```
node scripts/generate-icons.js     # 生成 src/constants/icons.ts（别手改）
  ↓
pnpm exec tsx scripts/generate-lqips.ts   # 生成 src/constants/lqips.json
  ↓
astro build                        # 静态输出到 dist/
  ↓
node scripts/copy-pio-assets.mjs   # 看板娘资源**按需**复制到 dist/pio（见 §7.4）
  ↓
pagefind --site dist               # 生成搜索索引
```

`build:fast` 只省掉最后一步 pagefind（本地验证够用）。

### 5.3 运行期：主题与显示设置

```
首屏：Layout.astro 的内联脚本（必须同步、先于渲染）
  readStore("theme") → resolveTheme() → <html class="dark"> + data-theme
  readStore("contentFontScale") → 设置 --content-font-scale
  ↓
用户改设置：DisplaySettingsIntegrated.svelte
  → setting-utils / storage-utils 写入 localStorage
  → 同步更新 <html> 上的 CSS 变量或 class
```

**相关 localStorage 键**（改动时注意兼容老用户存档）：
`theme`、`hue`、`wallpaperMode`、`overlayOpacity`、`overlayBlur`、`overlayCardOpacity`、`bannerCarouselEnabled`、`bannerTitleEnabled`、`wavesEnabled`、`gradientEnabled`、`sakuraEnabled`、`postListLayout`、`contentFontScale`、`music-player-volume`、`ad-closed`。

### 5.4 站内导航（swup）

`astro.config.mjs` 中 swup 的 `containers`：

```js
["#banner-overlay-container", "#banner-dim-container", "#swup-container",
 "#left-sidebar-dynamic", "#right-sidebar-dynamic", "#floating-toc-wrapper"]
```

导航时**只替换这些容器**。因此：

- 容器外（如 `<body>` 末尾的全局脚本）**不会**随导航重新执行；
- 容器内、且**未标** `data-swup-ignore-script` 的脚本会被 `SwupScriptsPlugin` 重新执行 —— 这是本项目的通用做法；
- swup **v4 只派发 `swup:<hook>` 形式的事件**（如 `swup:page:view`、`swup:content:replace`）。旧版驼峰名（`swup:contentReplaced` / `swup:pageView` / `swup:enable`）**永不触发**，不要照抄旧代码。
- `@swup/astro` 会额外转发 `astro:page-load` / `astro:before-swap` / `astro:after-swap`，但**只在 swup 导航后触发，首次加载不触发**。

### 5.5 音乐播放器

- `MusicManager.astro`：全局**单例**，持有唯一 `audio` 元素，通过 `CustomEvent`（`fm:*` 系列）同步所有视图实例。
- `MusicPlayer.astro`：纯 UI 视图控制器（侧栏/导航栏可能有多个实例），委托管理器操作。
- 数据源：`musicPlayerConfig.mode` = `"meting"`（外部 API）或 `"local"`（本地列表）。

### 5.6 搜索

构建期由 pagefind 生成索引，**索引只在 `pnpm build` 最后一步生成**；用 `build:fast` 本地预览时搜索不可用。`pagefind.yml` 排除了 KaTeX 与 `[data-pagefind-ignore]` 内容。

## 6. 本地环境搭建与启动

```bash
# 1) 安装 pnpm（若未安装）
npm i -g pnpm@9.14.4
```

### 7.2 环境变量

本项目**几乎不需要环境变量**，`.env` 也未纳入依赖。代码中使用的都是 Astro 内置变量：

| 变量 | 含义 | 使用处 |
|---|---|---|
| `import.meta.env.BASE_URL` | 站点 base（配置为 `/`） | `url-utils.ts`、`layout-utils.ts`、`Layout.astro`、`gallery-utils.ts` |
| `import.meta.env.DEV` / `.PROD` | 开发/生产判定 | 搜索组件、`bangumi.astro`、`Navbar.astro` |
| `import.meta.env.SITE` | 站点绝对地址 | `pages/robots.txt.ts` |
| `process.env.CF_WORKERS` | **构建时**决定是否启用 Cloudflare adapter | `astro.config.mjs` |
| `process.env.NODE_ENV` | 构建环境 | `astro.config.mjs` |

> 关键：`site` 来自 `siteConfig.site_url`，**改站点地址请改配置，不要改环境变量**。

### 7.3 部署配置

- `wrangler.jsonc`：`name: firefly`、`assets.directory: ./dist`、`compatibility_flags: ["nodejs_compat"]`
- `vercel.json`：`buildCommand: pnpm build`、`outputDirectory: dist`、`installCommand: pnpm install`，并配置了一批安全响应头
- **Cloudflare 的构建命令必须是 `pnpm build`**（而不是只跑 `astro build`），否则 `copy-pio-assets.mjs` 不会执行。

### 7.4 看板娘资源（特殊机制）

`pio-assets/` **不在 `public/` 下**，因为它有 **14.62 MB**（单个 wav 7.14 MB）。
`scripts/copy-pio-assets.mjs` 在 `astro build` **之后**读取 `src/config/pioConfig.ts` 的 `enable`：

- 任一看板娘启用 → 复制 `pio-assets/` → `dist/pio/`（URL 仍是 `/pio/...`，无需改路径）
- 都关闭 → **不复制**，并**主动清掉** `dist/pio` 里的残留副本
- 解析不到开关 → **按"已启用"处理**（宁可多传体积，也不允许"配置开了但模型找不到"）

### 7.5 文章附件下载

文章可声明一组可下载附件（zip / pdf / html 等），在**文末**渲染为卡片式下载区块（正文结束、版权信息之前）。

**声明方式**（frontmatter，`posts` schema 的可选字段，缺省为空数组，**老文章不会构建失败**）：

```yaml
attachments:
  - path: files/my-post/课件打包.zip   # 站点根相对路径 → 对应 public/files/my-post/课件打包.zip
    name: 课件打包                     # 可选，缺省用文件名
  - path: https://example.com/x.zip    # 也支持外链（外链不显示大小）
    name: 备用地址
attachmentsProtected: false           # 可选；true 时隐藏整个下载区块
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `attachments[].path` | ✅ | 站点根相对路径（对应 `public/` 下），或 `http(s)://` 外链 |
| `attachments[].name` | ❌ | 显示名，缺省取文件名 |
| `attachmentsProtected` | ❌ | 默认 `false`；`true` 隐藏下载区块 |

**实现要点**：

- 附件放 `public/files/<slug>/`，Astro 原样拷进 `dist/`（按文章分子目录，便于迁移清理）。
- 文件大小**构建期用 `node:fs` 读取**（`src/utils/attachment-utils.ts` 的 `resolveAttachments`），frontmatter 永不手写 size。
- **本地文件缺失 → 构建直接失败**并给出明确错误，不静默产出坏链。
- URL 一律走 `url-utils.url()`；中文文件名用 `encodeURI` / `decodeURIComponent` 处理。
- 类型用**扩展名文本徽标**（`ZIP`/`PDF`/`HTML`…），**不引入新的 iconify 图标名**——`src/constants/icons.ts` 由 `scripts/generate-icons.js` 生成且被 `Icon.svelte` 当白名单消费，**用了清单外的图标名会直接失败**。新增图标后要跑 `pnpm icons`。
- HTML 附件**强制下载**（`download` 属性），不在本站源下内联执行。

⚠️ **边界**：附件是**公开直链**。即使文章设了 `password`，直链拿到就能下载——加密保护的是正文，不是附件。`attachmentsProtected: true` 只是**隐藏入口**，文件仍可被直接访问；真正的访问控制需外部存储 + 签名 URL。

详细方案见 `docs/附件下载功能方案.md`。

## 8. 代码组织规范与开发约定

### 8.1 Astro 脚本块：**先判断再改**（最容易踩的坑）

同一个 `.astro` 文件里可以并存两种脚本块：

| 写法 | 是否打包 | 能否 `import` | 导航后是否重跑 |
|---|---|---|---|
| `<script>`（默认） | 是 | **可以** | 模块体只执行一次（ESM 缓存） |
| `<script is:inline>` | **否** | **不可以** | 会被 `SwupScriptsPlugin` 重新执行 |

**硬规则**：

1. 做"引入工具函数"这类迁移时，**必须逐块判定**（看属性里有没有 `is:inline`），**绝不整文件替换**。
2. 内联脚本需要公共逻辑时，用**就地小函数**（如 `__sfStoreGet`），不要试图 import。
3. 模块脚本里**不要**写 `if (window.swup?.hooks) hooks.on(...)` —— swup 初始化晚于模块执行，该分支会被跳过且永不重试。改用**无条件** `document.addEventListener("swup:page:view", fn)` 或 `utils/navigation-utils.ts` 里的 `waitForSwup()`。

### 8.2 注释写法

- **不要**用 `<!-- HTML 注释 -->`：会被**原样输出**到产物页面（白占字节、暴露内部说明）。
- 写给自己看的说明用 **`{/* 表达式注释 */}`**，构建时会被剥掉。
- ⚠️ `{/* */}` **只能放在模板顶层的表达式容器里**。写成 `{cond && ( {/* 注释 */} <tag/> )}`（注释落在 JS 表达式内部）会**编译失败**（esbuild 报 `Expected ")" but found "$$render"`）。
- 表达式注释里**不要再出现 `*/`**（哪怕写成 `{/* */}` 这个字样），会提前闭合块注释。

### 8.3 本地存储

**一律走 `src/utils/storage-utils.ts`**，不要直接用 `localStorage`：

```ts
getStorageItem(key) / setStorageItem(key, value) / removeStorageItem(key)
getStorageJSON<T>(key, fallback) / setStorageJSON(key, value)
```

原因：`localStorage` 在**隐私模式 / 配额超限 / 禁用站点数据**时会**抛异常**（不是返回 null）。该封装全部 try/catch，失败退到**内存兜底**。
`is:inline` 脚本无法 import，就地定义同名小函数即可（见 `SakuraEffect.astro`、`MusicManager.astro`）。

### 8.4 国际化

- `src/i18n/i18nKey.ts` 是一个 **enum**（约 271 条），新增文案：① 加 enum 成员 ② 在 `languages/{en,ja,ru,zh_CN,zh_TW}.ts` **五个文件都补齐**。
- 使用：`i18n(I18nKey.xxx)`。**用户可见文案一律走 i18n**，不要硬编码。

### 8.5 样式

- Tailwind v4：入口 `src/styles/main.css`（`@import 'tailwindcss'`），其余 css 由它引入。
- 主题变量在 `src/styles/variables.styl`（`:root` 与 `.dark` 两套）。
- **暗色覆盖写法统一用 `:root.dark`**（项目已有约 20 处），**不要用 `@media (prefers-color-scheme: dark)`** —— 它响应的是操作系统，与站内主题开关不一致。
- 正文样式集中在 `src/styles/markdown.css`（`.custom-md`）。

### 8.6 代码风格（biome）

- **缩进用 Tab**，字符串用**双引号**（`biome.json` 强制）。
- import 会自动排序（`organizeImports: on`）。
- 提交前跑：`pnpm lint`（自动修复）→ `pnpm check`。
- `.css` 文件被 biome 排除；`src/constants/icons.ts` 与 `lqips.json` 是生成物，也被排除。

## 9. 注意事项

### 9.1 常见易错点

| 易错点 | 说明 / 正确做法 |
|---|---|
| **用错包管理器** | `preinstall` 强制 pnpm，用 npm/yarn 会失败 |
| **手改生成物** | `src/constants/icons.ts`、`src/constants/lqips.json` 由脚本生成，改了会被覆盖 |
| **小部件里写死 `id`** | 同一小部件在桌面侧栏与移动底栏**各渲染一份** → 会重复。改用 `class`（现有做法：折叠容器用 `collapse-<id>` class） |
| **`{/* */}` 放错位置** | 放进 `( ... )` 表达式内部会导致**编译失败**，见 §8.2 |
| **`is:inline` 里 import** | 内联脚本不参与打包，**无法 import**，会直接报错 |
| **照抄旧 swup 事件名** | swup v4 只有 `swup:<hook>`，旧的 `swup:contentReplaced` 之类**永不触发** |
| **手工拼文章 URL** | 一律用 `url-utils.getPostUrlBySlug()`，它会处理扩展名与 base |
| **用 `prefers-color-scheme` 做暗色** | 要跟站内主题一致，用 `:root.dark`，见 §8.5 |
| **Windows 上用文本模式改文件** | Python/部分工具会把 `\n` 写成 `\r\n`，导致整文件行尾变更（本项目要求 **LF**）。改文件用二进制或显式 `newline=''` |
| **`dist/` 不是源码** | 它是构建产物且已 gitignore；**验证请读 `dist/`，不要改它** |

### 9.2 修改代码的影响范围与风险提示

| 你要改的地方 | 影响范围 | 风险与建议 |
|---|---|---|
| `Layout.astro` 脚本部分（含内联主题引导） | **全站**、首屏、swup 导航 | 风险最高。内联脚本必须在渲染前同步跑完，任何异常都会让"无样式/无主题"直接暴露给用户 |
| swup `containers` 列表 | 站内导航行为 | 加/删容器会改变"导航时替换什么"，影响脚本重跑与动画 |
| `sidebarConfig.ts` | 侧栏组件顺序与分布 | 顺序即渲染顺序；注意 `showOnPostPage` / `showOnNonPostPage` |
| 小部件组件（`widget/`） | 桌面**和**移动底栏两处 | 改一处等于改两处渲染 |
| CSS 断点 / `!important` / 全局色值 | 全站视觉 | 需**三档视口 × 深浅色**回归；这类改动建议小批量、分批验证 |
| `content.config.ts` schema | 全站文章 | 加必填字段会导致老文章**构建失败**；新增字段请给 `.optional().default(...)` |
| `getRelatedPosts` 打分逻辑 | 每篇文末的"相关文章" | 纯构建期，不影响运行期性能，但会改变所有页面的输出 |
| `api/allPostMeta.json.ts` | 随机文章 + 日历组件 | 两端共用，改结构要同时改两处消费方 |
| 音乐播放器 | 单例管理器 + 多个视图实例 | 视图实例不得各自持有 audio；状态同步走 `CustomEvent` |
| `pioConfig` 开关 | 部署体积（±14.6 MB） | 启用后务必确认 CF 构建命令是 `pnpm build`，否则资源不会进 `dist` |

### 9.4 已知限制与待改进

1. `banner` 这个 `id` 在单页中会出现 **6 次**（桌面默认图 + 各轮播模板 + 移动端同构）。目前靠"取第一个"工作，**属历史遗留**；清理需同步改 `Layout.astro` 的 `#banner` 用法与 `layout-styles.css` 的 `#banner img`，应单独进行并做视觉回归。
2. 同一小部件在桌面与移动端**各渲染一份** DOM（`left/right-sidebar-dynamic` 与 `mobile-bottom-sidebar`）——重复渲染带来 HTML 体积与重复 id 隐患，需用 CSS 重排替代前**先确认移动端底栏行为**。
3. 全站硬编码色值仍有数百处，`!important` 亦较多（`navbar.css`、`layout-styles.css`）——属维护性债，改动需视觉回归，不宜一次大改。
4. `astro check` 当前有 **35 个既有类型错误**（如 `Layout.astro` 的 `storedTheme` 类型问题）。**新增改动不应让这个数字变大**，它是判断"是否引入新问题"的有效基线。
5. 部分大组件体积偏大（`DisplaySettingsIntegrated.svelte`、`MusicPlayer.astro` 等），拆分属低收益高风险的维护性工作。
6. `experimental.rustCompiler` 目前为 `false`（部分平台会构建失败），`queuedRendering` 已开启。

### 9.5 协作与交付约定（重要）

这是本项目实际采用的协作流程，请照此执行：

1. **先验证，再提交，最后推送**；验证不通过就**中止，不提交**。
   - 每次提交前跑：`pnpm lint`（biome 必须零错误）→ `pnpm check`（`astro check`，错误数不得高于既有基线）→ 构建。
   - **不要**把 lint 报错连同"看起来通过"一起提交。
2. **构建产物验证走"产物核对"**：改完跑一次构建，再从 `dist/` 里核对目标是否达成（如标题层级、重复 id 计数、CSS 变量是否落地），而不是只看代码。
3. **提交用精确暂存**（`git add -- <明确路径>`），**不要 `git add -A`**。
4. **本地工作文档不入库**：`完善计划.md`、`日志.md`、`执行清单.md`、`操作指南.md` 与 `.workbuddy/` 都已在 `.gitignore` 中，属本地资料，**不要提交**。
5. **涉及视觉的改动必须留证据**：改前/改后各截一组（三档视口 × 深浅色）再比对；“像素级无差异”类改动尤其如此。
6. **行为类改动需人工复验**：例如折叠交互、键盘可达性、字号调节等，静态检查查不出来，要在浏览器里实际点一遍（桌面端与移动端各一次）。
7. **遇到命令莫名卡死**：先停掉任务，检查是否有 `.git/*.lock` 残留（尤其是 `.git/index.lock`），清理后**重跑一次**再判断（本环境多次出现"同一操作重跑即成功"）。
8. **工作区恢复只用 `git restore -- <路径>`**，**禁止** `git reset --hard` / `git clean -fd`。
9. **删除类操作前先确保工作区已提交并推送** —— 历史教训：一次批量文件消失事件中，能无损恢复的唯一原因就是所有内容都在提交里。
10. **对"某处有问题"的判断，先做一次最小实测再动手**。本项目多次出现"阅读代码推断出的缺陷"经实测并不成立的情况（死代码、已有覆盖、体积估算错误等），先量再改可以省掉整轮返工。
