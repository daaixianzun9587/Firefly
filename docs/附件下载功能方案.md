# 文章附件下载功能 · 实现方案

> 目标：文章除了正文，还能提供 zip / html / pdf 等文件的下载入口。
> 本方案已通过需求追问（Grill Me）确认，所有决策见 §1。

---

## 1. 决策汇总（已确认）

| 维度 | 决策 | 理由 |
|---|---|---|
| 存放位置 | `public/files/<slug>/<文件名>` | Astro 原样拷进 `dist/`；按文章分子目录，便于迁移与清理 |
| 数据声明 | frontmatter 数组 `attachments`，可选、默认 `[]` | 老文章**零迁移**，不会构建失败 |
| 保护策略 | **默认公开直链**；`attachmentsProtected: true` 时隐藏下载区块 | 规则简单一致；真要保护时由作者显式开启 |
| HTML 处置 | **强制下载**（`download` 属性 + `nosniff` 响应头），不内联预览 | 避免第三方 HTML 在本站源下执行脚本（存储型 XSS / 钓鱼） |
| UI 位置 | 文章**文末**卡片（正文结束、版权信息之前） | 不挤占正文；仅部分文章有的内容不适合进侧栏 |
| 点击行为 | `<a download target="_blank" rel="noopener">`，显示扩展名徽标 + 文件名 + 大小 | 浏览器按类型自然处理（PDF 预览、zip 下载） |
| 文件大小 | **构建期用 `node:fs` 读取**，frontmatter 不写 size | 永不手写、永不过期 |
| 缺失处理 | 本地文件不存在 → **构建失败**并给出明确错误 | 不静默产出坏链 |
| 列表页标识 | **不做**（首页/归档卡片不显示附件图标） | 避免为展示需求改动集合查询的数据流，后续可加 |

### 已知边界（必须在文档中明示）

> **附件是公开直链。** 即使文章设置了 `password` 加密，只要有人拿到附件 URL 就能直接下载。
> 加密保护的是**正文**，不是附件。需要保护时请在 frontmatter 设置 `attachmentsProtected: true`
> （该开关会隐藏整个下载区块，但**文件本身仍在 `public/` 下可被直接访问**——
> 若要真正的访问控制，需改用外部存储/CDN 的签名 URL，不在本方案范围内）。

## 2. 数据结构

### 2.1 frontmatter 写法

```yaml
---
title: 我的文章
published: 2026-09-24

# 可选。附件列表，按顺序渲染
attachments:
  - path: files/my-post/课件打包.zip      # 相对站点根（对应 public/files/my-post/课件打包.zip）
    name: 课件打包                        # 可选，缺省用文件名
  - path: files/my-post/report.pdf
  - path: https://example.com/big.zip     # 也支持外链（此时无法读取大小，显示"—"）
    name: 备用下载地址

# 可选，默认 false。为 true 时不在页面渲染下载区块
attachmentsProtected: false
---
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `attachments[].path` | ✅ | 站点根相对路径（对应 `public/` 下），或 `http(s)://` 外链 |
| `attachments[].name` | ❌ | 显示名，缺省取文件名（不含扩展名） |
| `attachmentsProtected` | ❌ | 默认 `false`；`true` 时隐藏下载区块 |

### 2.2 zod schema（`src/content.config.ts`）

```ts
attachments: z
  .array(
    z.object({
      path: z.string(),
      name: z.string().optional().default(""),
    }),
  )
  .optional()
  .default([]),
attachmentsProtected: z.boolean().optional().default(false),
```

> 用 `.optional().default(...)` 是关键：老文章没有这些字段**不会**构建失败。

## 4. 核心实现要点

### 4.1 `src/utils/attachment-utils.ts`

```ts
// 只导出本功能需要的函数
export interface AttachmentItem {
  name: string;      // 显示名
  url: string;       // 最终 href（走 url() 处理 base）
  size: number | null;   // 字节；外链或异常时为 null
  sizeText: string;      // "1.2 MB" / "—"
  ext: string;           // "zip" / "pdf" / "html" …
  isExternal: boolean;
}

export function resolveAttachments(raw: unknown[]): AttachmentItem[]
```

职责与约束：

1. **URL 生成一律走 `url-utils.url()`**，不手工拼字符串（处理 `BASE_URL`）。
2. **大小在构建期用 `node:fs.statSync` 读取** `public/<path>`：
   - 外部链接（`http://` / `https://` 开头）**不读**，size 为 `null`，显示 `—`；
   - 中文/带空格的文件名先 `decodeURIComponent` 再定位；
   - 读取失败抛错，由调用方转为构建错误。
3. **本地文件不存在 → 抛出明确错误**（含文章 slug 与 path），让构建**失败**而不是产出坏链。
   这是刻意的：坏下载链接是真实缺陷，CI 阶段发现好过线上发现。
4. **类型判定取扩展名小写**：`zip`/`pdf`/`html`/`doc`/`xls`/`ppt`/`png|jpg|webp|avif`/`txt`/其它。
5. `formatFileSize`：`< 1024` 显示 B，`< 1 MB` 显示 KB，否则 MB（保留一位小数）。

### 4.2 `src/components/misc/PostAttachments.astro`

- Props：`attachments`（原始数组）、`slug`（用于错误信息）、`protected`（布尔）。
- **渲染前置条件**：`protected === true` → 不渲染；`attachments` 为空 → 不渲染。
- 结构（复用现有 `.card-base` 与小部件标题风格）：

```
┌ 附件下载 ─────────────────┐
│ [PDF] report.pdf      1.2 MB  [↓ 下载] │
│ [ZIP] 课件打包.zip     8.4 MB  [↓ 下载] │
└──────────────────────────┘
```

- **类型用「扩展名徽标」文本**（`PDF` / `ZIP` / `HTML` …），**不引入新的 iconify 图标名**——
  避免"图标名在图标集中不存在"导致构建失败；下载按钮用**已存在**的 `material-symbols:download`。
- 每条链接：`<a href={url} download target="_blank" rel="noopener noreferrer">`。
  - `download` 属性让浏览器优先下载（对 HTML 尤其重要，防止内联执行）；
  - `rel="noopener noreferrer"` 是外链安全要求。
- 空数组 / 全被过滤 → 组件整体不输出任何 DOM。

### 4.3 挂载位置

在 `src/pages/posts/[...slug].astro` 中，紧跟正文、位于 `License` 组件**之前**插入：

```astro
<PostAttachments
  attachments={entry.data.attachments}
  slug={entry.id}
  protected={entry.data.attachmentsProtected}
/>
```

新增两个键，五语补齐：

| 键 | 简体 | 繁体 | English | 日本語 | Русский |

## 5. 安全与风险

| 风险 | 处置 |
|---|---|
| 第三方 HTML 在本站源执行脚本 | 强制 `download`；部署侧已有 `X-Content-Type-Options: nosniff` |
| 外链被用作钓鱼/跳转 | 外链统一 `target="_blank" rel="noopener noreferrer"` |
| 加密文章的附件可被直链下载 | 已在 §1 明示边界，并提供 `attachmentsProtected` 开关；真正的访问控制需外部存储 |
| 仓库/部署体积膨胀 | 约定"单文件 < 5 MB、总量 < 50 MB"；超限时迁移到 `pio-assets` 那套按需复制机制 |
| 中文文件名无法访问 | 用 `encodeURI` 生成 href，磁盘定位用 `decodeURIComponent` |
| 坏链静默上线 | 构建期校验，缺失即失败 |

## 6. 验证方式

1. **lint**：`pnpm lint`（biome 零错误）
2. **类型/模板**：`pnpm check`（`astro check` 错误数**不得高于既有基线 35**）
3. **构建**：`pnpm build`（若附件路径写错，此处应**明确报错**）
4. **产物核对**（读 `dist/`）：
   - `dist/files/<slug>/<文件名>` 存在（Astro 拷贝了 `public/`）；
   - 文章页 HTML 中出现 `附件下载` 区块，含 `<a ... download ...>` 与大小文本；
   - 未声明附件的文章**不出现**该区块。
5. **浏览器复验**：
   - 点 zip → 直接下载；点 pdf → 新标签预览/下载；点 html → **下载而非打开**；
   - 设 `attachmentsProtected: true` → 区块消失；
   - 深/浅色主题下区块样式正常。
